# CmsPro-投票系统-使用指南

> 版本：1.0.0 | 更新日期：2026-11-05
> 适用应用版本：1.0.0 | 应用 ID：cmspro.polling

---

## 一、应用简介

投票系统是一个支持多活动的用户投票应用，覆盖**后台管理、用户中心、官网前台**三端，提供单选、多选、排序三种投票类型，内置防刷票（限投次数、同 IP 限制、需登录投票）、匿名投票、实时统计与 CSV 导出能力。

典型使用场景：

| 场景 | 推荐配置 |
|------|----------|
| 在线问卷调查与投票 | 多选投票（max_choices=3~5）、结果实时可见、游客可投 |
| 社区话题投票决策 | 单选投票、需登录投票、投票后可见、每人限投 1 次 |
| 活动评选投票 | 排序投票（Borda 计分）、需登录 + 同 IP 限制、结束后可见、匿名投票 |

## 二、安装与卸载

### 2.1 安装

1. 后台进入 **应用管理**，通过本地安装或应用市场安装本应用；
2. 安装脚本会自动：创建 3 张业务表 → 写入默认配置 → 创建一个示例投票活动「你最期待的投票功能是什么？」；
3. 安装完成后，后台左侧菜单出现 **投票管理**（活动管理、投票记录），用户中心出现 **我的投票**，官网前台导航出现 **投票**。

### 2.2 卸载

卸载会回滚全部数据表（活动、选项、投票记录一并删除）并清理应用缓存，**操作不可逆**，请先导出需要的统计报告。

## 三、后台管理

### 3.1 创建投票活动

进入 **投票管理 → 活动管理 → 新建活动**，按分区填写：

| 分区 | 字段 | 说明 |
|------|------|------|
| 基本信息 | 标题 / 描述 / 排序 | 标题必填，最多 200 字 |
| 时间设置 | 开始 / 结束时间 | 可留空表示不限时；结束时间必须晚于开始时间；**到达结束时间后活动在运行时自动视为已结束，无需手动操作** |
| 投票规则 | 投票类型 / 最多可选（多选时）/ 需要登录 / 每人限投次数 / 同 IP 限制 / 匿名投票 / 结果可见性 | 详见下文规则说明 |
| 投票选项 | 选项标题 / 描述 / 图片 | 至少 2 个有效选项；支持上移、下移、删除 |

**投票规则说明：**

- **投票类型**
  - 单选投票：每人每批次只能选 1 个选项；
  - 多选投票：可设「最多可选」数量（至少 2，且不能超过选项数）；
  - 排序投票：投票人按偏好对选项排序（至少排 2 个），结果按 **Borda 计分** 排名——选项每被排第 N 名得「选项总数 − N」分（不减为负），得分高者胜出，同时统计每个选项的名次分布。
- **每人限投次数**：默认 1 次。登录用户按账号计数；游客按 IP 计数（同一 IP 的游客共享额度）。
- **同 IP 限制**：同一 IP 在该活动的总提交批次数上限（含登录用户），0 为不限制。适合公开评选防刷。
- **匿名投票**：开启后统计导出与记录中的投票人显示为「匿名」。
- **结果可见性**：实时可见 / 投票后可见 / 结束后可见 / 不公开。

### 3.2 活动状态管理

活动有三种状态：**草稿 → 进行中 → 已结束**。

- 草稿：不出现在前台，不可投票；
- 进行中：前台可见、可投票（受时间窗口约束）；
- 已结束：前台列表不再展示（详情页仍可看结果，取决于可见性）。

列表页的状态列同时展示「运行时状态」：即使状态仍为「进行中」，只要已过结束时间即显示「已结束」并停止投票。

**注意**：已产生投票记录的活动不允许更换投票类型（避免历史数据计分错乱），其余字段仍可修改。
编辑选项时，携带原有选项 ID 的执行原地更新（投票记录不悬空）；已被投票的选项无法删除
（提交时遗漏会被自动保留并在返回消息中提示）。

### 3.3 统计与导出

进入 **活动管理 → 统计**：

- 顶部汇总：参与人次（按批次去重）、总票数、选项数；
- 各选项条形图：单选/多选显示占比，排序投票显示 Borda 得分与名次分布（渐变色条）；
- 记录子表：该活动的全部投票记录；
- **导出 CSV**：需要「导出统计报告」权限，文件含 UTF-8 BOM 头（Excel 打开中文不乱码），内容为统计汇总 + 记录明细（匿名活动自动脱敏）。

### 3.4 投票记录查询

进入 **投票管理 → 投票记录**，支持按活动、选项、用户、IP、日期范围组合筛选。

### 3.5 全局配置

**系统设置 → 投票设置**（config_groups 由 manifest 声明）：

| 配置 | 默认值 | 说明 |
|------|--------|------|
| 默认每人限投次数 | 1 | 新建活动时的预填值 |
| 同 IP 投票限制 | 0 | 新建活动时的预填值 |
| 允许用户端发起投票 | 开启 | 关闭后用户中心「我的投票」仅可查看，不可发起 |

三个配置项均直读数据库，后台保存后**立即生效**（无需重启或清缓存）。

## 四、用户中心

登录后进入 **用户中心 → 我的投票**：

- **我发起的**：查看自己创建的活动（运行状态徽章实时显示），可预览、编辑、删除，仅能操作本人创建的活动（服务层强制 `limitUserId` 校验）；
- **参与记录**：我在所有活动中的投票历史（活动标题、所选选项、第几次投票、投票时间）；
- **发起投票**：受「允许用户端发起投票」全局开关控制；表单与后台一致，创建后默认为草稿或进行中，由用户自行发布。

## 五、官网前台

前台无需登录即可访问 **/cmspro/polling**：

1. **列表页**：仅展示「进行中」的活动卡片（标题、类型徽章、参与人次、截止时间）；
2. **详情页**：
   - 单选：点击选项即选中，再次提交前可更换；
   - 多选：多选选项（超过上限自动拦截并提示）；
   - 排序：按顺序点击选项，选项上显示名次徽章（1、2、3…），重新点击从头排序；
   - 需要「需要登录」的活动，游客会看到登录提示；
   - 提交成功后页面刷新，按结果可见性展示条形图统计；
3. **结果查看**：实时可见的活动始终展示统计；「投票后可见」在提交后出现；「结束后可见」在截止后出现。

## 六、常见问题

| 问题 | 原因与处理 |
|------|------------|
| 游客提示「该投票活动需要登录后参与」 | 活动开启了「需要登录」，请登录后投票 |
| 提示「您已达到该活动的投票次数上限」 | 已达到「每人限投次数」；登录用户按账号计，游客按 IP 计 |
| 提示「该IP的投票次数已达上限」 | 该活动的「同 IP 限制」已用尽，含登录用户的提交 |
| 活动明明是「进行中」却不能投票 | 已过结束时间，运行时自动判定为已结束 |
| 编辑活动时无法更换投票类型 | 该活动已有投票记录，为保护历史数据禁止换类型；可删除活动后重建 |
| 前台看不到我的活动 | 活动处于草稿状态，或已过结束时间 |
| 导出的 CSV 用 Excel 打开乱码 | 本应用导出自带 BOM 头；若乱码请确认使用本应用的导出按钮而非另存网页 |
| 用户中心无法发起投票 | 后台「允许用户端发起投票」开关已关闭 |
